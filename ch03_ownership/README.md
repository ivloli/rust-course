# 03 所有权、借用与生命周期

```bash
cargo run -p ch03_ownership
```

这一章是 Rust 的核心。建议把注释掉的「编译错误」逐个放开，亲自看一次报错。

## 三条所有权规则

1. 每个值有且只有一个所有者（owner）。
2. 同一时刻只能有一个所有者。
3. 所有者离开作用域时，值被自动释放（drop）。

## 代码导读（src/main.rs）

1. `let s2 = s1;` 是移动而不是浅拷贝：`s1` 之后不可用，避免 double free。
2. `clone()` 复制堆数据，代价真实存在；不要为了「能编译」而到处 clone。
3. `i32` 实现了 `Copy`，赋值等价于按位复制，原变量仍可用。
4. 不可变借用 `&T` 可以同时存在多个；可变借用 `&mut T` 必须独占。
5. `&str` 切片借用原字符串，不复制内容；`first_word` 的返回值生命周期由入参决定。
6. `longest<'a>` 是生命周期标注的典型例子：签名承诺「返回值活得和较短的那个入参一样久」。

## 动手练习

1. 取消 `println!("{s1}")` 的注释，读完整条编译器错误与建议（`help: consider cloning`）。
2. 写一个 `fn longest_word(words: &[String]) -> Option<&str>`，不 clone 任何 String。
3. 解释为什么 `&mut s4` 之后再 `println!("{s4}")` 是合法的（NLL，非词法生命周期）。
4. 把 `first_word` 改为返回 `&str` 的切片（用 `find(' ')`），体会返回值仍借用原串。
5. 思考：Web 服务里 handler 为什么常常接收 `String` / `Json<T>` 而不是 `&str`？（提示：`'static` 与跨 await 持有）

## 工程提醒

- 生命周期标注不会「延长」任何值的寿命，只是描述关系。
- 遇到借用冲突，优先考虑缩小作用域、拆分结构体字段，而不是无脑 `clone`。
